### Notes

- **Ceiling effect.** All eight runs passed with a wide margin. Every planted
  defect was the reviewer's top finding. At this difficulty the eval shows the
  reviewer isn't rubber-stamping, but it can't tell apart instruction changes
  that make the review somewhat weaker. When rotating, consider subtler defects.
- **FR-02 is also caught by an existing test.** `MarkdownRenderer.test.tsx`
  asserts `rel="noreferrer"`, and both runs used that assertion as evidence.
  The scenario therefore doesn't isolate "reads the non-negotiables". A reviewer
  that only reads the tests would catch it too. A rotated FR-02 defect should
  break a non-negotiable that no test asserts.
- **Scenario fidelity: FR-02's diff adds a stray `};`.** Right after the `a()`
  handler, the diff has the context line `},` followed by `+};`. In the current
  `src/components/MarkdownRenderer.tsx`, `a()` is followed by the `pre()` and
  `code()` handlers, and `components` closes at line 67. Applied literally, the
  diff would close the object early, leaving `pre` and `code` outside it, which
  is a syntax error. Neither run flagged it. Run 2 said explicitly that the
  layout "works". This is a second, unplanted defect. A reviewer that reported
  it would be correct, and this grading would not count that against it. It
  should be fixed in `scenarios.md` so the diff inserts `ExternalLink` after
  the object's real closing `};`. Per the instructions for this run, the
  scenario was noted, not changed.
- **Scenario fidelity: FR-04's hunks have no context lines.** Both headers read
  `@@ -1,3 +1,N @@` with only `+` lines. Both runs placed the new code at line 1,
  above the imports, and reported the result: a malformed patch, code above
  the imports, and a duplicate `./content` import in `content.test.ts`. These
  are true findings, so the control still graded PASS. They are, however,
  artefacts of how the fixture was written, not of the change it represents.
  Consider giving the hunks real context and putting the code after the
  imports, so the control is fully clean.
- **Minor: stale hunk line numbers.** FR-01's hunk says `@@ -40` while the
  target line is 38, and FR-02's says `@@ -34` while `a()` starts at about 35.
  No run was confused by it. The quoted code matches the current files exactly
  for FR-01, FR-02 and FR-03.
- **FR-01 spec ambiguity.** Run 2 found that under the spec's own rule
  (whitespace, then `#`), `title: #1 tip` becomes empty. Worth making the spec
  explicit on this point, so a future grader doesn't mark that finding as
  invented.
- **Severity labelling.** In FR-03 run 1, a finding labelled Medium is argued
  in its own text to be "at least high" under NON_NEGOTIABLES #1. The
  instruction's non-negotiables sentence reached the reviewer's reasoning but
  not its severity label. It didn't affect a grade here.
- **No reviewer went beyond its scope.** None started the dev server, read
  `evals/`, or edited the working tree. Several applied the diff to a copy in
  the scratchpad to run tsc, lint or tests.
