## Notes

- **`SDN-20` found a real gap.** The agent opened the diagnosis page, found no
  row for "one of my own servers hangs and needs restarting by hand", and
  concluded that no question covers automatic restarts, even though the catalog
  has `self-healing-systems`. The cause was the failing-service question's
  summary, which described only "a failing dependency", so a reader with a hung
  instance of their own had no reason to open it. Two fixes: the summary now says
  "a failing dependency or a hung instance ... and automatic restarts", and the
  diagnosis page's routing table has a row for the symptom. A re-run reached the
  failing-service question first and `self-healing-systems`; the neighbouring
  `SDN-06`, `SDN-07` and `SDN-14` were re-run against the new summary and still
  pass. This is the second time a routing fix has been a signpost on the
  diagnosis page plus a summary that names the symptom.
- **`SDN-10` and `SDN-11` did not drift to question 8**, although its page also
  links `outbox-pattern` and `saga-pattern`. Both stay unambiguous.
- **`SDN-05`'s agent suggested `message-queues`** for an async ingest path even
  though the writes question doesn't link it (it said so itself). The writes
  question routes to `batching-and-asynchronous-writes`, which mentions queues.

- **`SDN-18` reached the caching topic through the reads question**, and the

  not by the title.
