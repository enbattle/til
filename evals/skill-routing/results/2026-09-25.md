## Notes

- **The new section did not change any routing decision.** SR-03 and SR-06
  both cited it, and both read it correctly: it governs how a direct fix
  lands (branch, PR, CI), not whether the fix is direct. Neither treated it as
  a reason to escalate to `/feature`.
- **SR-08 failed, and not because of the new section.** Its reasoning never
  mentions "How changes land"; it rests on the general "nontrivial change"
  rule and says outright that nothing in `CLAUDE.md`, `docs/` or
  `feature/SKILL.md` covers dependency updates. It also did not mention
  `npm run verify` or Dependabot. The two previous runs on 2026-09-24 passed
  SR-08 but also noted that no doc covers dependency updates, so this looks
  like a latent gap that the general rule leaves to judgment rather than a
  regression. A one-line note in `CLAUDE.md` (a dependency bump is direct,
  gated by `npm run verify`) would close it; not done here, since this run was
  scoped to editing only the results file.
